# 咔一下子音乐 · 服务端部署

**把你 NAS 上的一个音乐目录，变成一台音乐服务器。**

扫目录建库（递归子文件夹）→ 网页播放 → 桌面版 / TV 版客户端能自动搜到它，不用填 IP。

```
┌──────────────────┐      自动发现          ┌──────────────────┐
│  播放器           │ ───────────────────▶  │  下载部件（可选） │
│  扫库 / 播放       │                       │  go-music-dl     │
│  客户端可发现      │ ◀───────────────────  │  搜歌 / 下歌      │
└──────────────────┘                       └──────────────────┘
      只读挂载你的音乐目录                  下载直接落进曲库的「下载」子目录
```

---

## 一、三步起来

```bash
# 1) 复制配置，把 MUSIC_DIR 改成你自己的音乐目录
cp .env.example .env
vi .env                      # MUSIC_DIR=/你的/音乐目录

# 2) 拉镜像
docker compose pull

# 3) 起（一条命令起两个容器：播放器 + 下载部件）
docker compose up -d
```

打开 **`http://这台机器的IP:8580`**。

> 目录里没歌也能起，只是曲库是空的。放歌进去后 30 秒内会自动扫到，不用重启。

---

## 二、下载部件

上面那条 `docker compose up -d` 会同时起两个容器：

| 容器 | 干什么 | 端口 |
|---|---|---|
| `kxyz-music` | 播放器：扫目录建库、播放、客户端可发现 | 8580 |
| `kxyz-dl` | 下载部件：搜歌下歌（go-music-dl） | 28001 |

**不用配任何东西它们就连上了** —— 播放器启动后自己会找到同机的下载部件（60 秒内），
网页顶栏就多出「下载」标签。下的歌落在 `${MUSIC_DIR}/下载/`，30 秒内自动进曲库。

下载部件自己的界面在 `:28001`（管各平台 cookie、看下载记录），平时不用碰。

**不想要下载部件？** 把 compose 里 `downloader:` 那一段整段删掉，再 `docker compose up -d`。
播放器不受任何影响，只是网页里没有「下载」标签。

> ⚠ **它的镜像在 Docker Hub，国内直连不通**（实测 `registry-1.docker.io` 10 秒超时）。
>
> 实测过的几个站，直接抄结论：
>
> | 地址 | 结果 |
> |---|---|
> | `docker.fnnas.com` | ✅ **226MB / 6.2 秒**（飞牛 NAS 自带，最快） |
> | `docker.1ms.run` | ⚠ 能下完，但 100 秒以上 |
> | `docker.m.daocloud.io` | ❌ 不在白名单，直接拒绝 |
> | 阿里云个人镜像加速器 | ❌ 已下线（返回 forbidden） |
> | `registry-1.docker.io` 直连 | ❌ 超时 |
>
> **compose 里已经默认写成飞牛镜像站的地址**，所以 `docker compose pull` 直接就能拉，
> 不用自己配加速器。你的网络能直连 Docker Hub 的话，换回 `guohuiyuan/go-music-dl:latest` 也一样。
>
> 拉不动又不想折腾，就把 `downloader:` 那一段整段删掉，只用播放器。

## 二·五、版本说明

镜像标签**用 `2.1.4`**（`latest` 与它内容相同）。2.1.1 是旧版，界面和接口都落后，别再用。

仓库里还有个 `2.1.0` 标签，那是早期版本，后来被重新指向了同一个最新镜像
（内容等同 latest）。阿里云个人版不支持删除单个标签，所以它一直留在列表里，
**不用管它，也别在文档里引用它**。详见项目内 `archive/README.md`。

## 三、客户端怎么连

| 客户端 | 怎么连 |
|---|---|
| 浏览器 | 直接开 `http://IP:8580` |
| 桌面版 exe | 登录页点「自动搜索」，或填 `IP:8580` |
| TV 版 | 选「Docker」源，遥控器按一下右键会自动搜 |

自动发现的判断依据是 `/api/health` 里 `app === "fnmusic"`，同网段扫 8530/8580。

## 四、让 AI 控制

配套两个 skill（`kxyz-music-remote` / `kxyz-music-librarian`），装上之后可以直接说
「放首歌」「暂停」「把缺的歌词补上」「删重复」。

AI 会自己扫局域网找服务器，不用告诉它 IP。

## 五、常见问题

**曲库一直是 0 首**
`MUSIC_DIR` 填错了，或者容器读不到那个目录。看日志：`docker logs kxyz-music | head -20`，
里面有一行 `音乐目录 ：/music`，再用 `docker exec kxyz-music ls /music | head` 确认能看到文件。

**网页打不开但容器是 running**
端口被占了。改 compose 里 `8580:8530` 的左边那个数字，客户端就改用新端口。

**某些歌名是 `??`**
这些文件的 ID3 标签是坏的（常见于老 WAV）。程序会自动退回用文件名，如果连文件名也乱就没救了。

**想换音乐目录**
改 `.env` 里的 `MUSIC_DIR` → `docker compose up -d`。索引会自己重建。

**升级**
改 compose 里 `image:` 的版本号 → `docker compose pull && docker compose up -d`。

**数据在哪 / 怎么备份**
只有 `./data`（曲库索引、封面缓存）和 `./dl-data`（下载部件的配置与记录）。
这两个丢了只是重建，**你的音乐文件一个字节都不会动**（只读挂载）。

## 六、自己构建镜像

```bash
docker build -f Dockerfile --target full -t fn-music:full .
```

`--target full` 是完整版（带播放器）。源码改完重建即可，不用动 compose。
